---

> **Важно:** Все цифры ниже — **оценки на основе ручного подсчёта по RTL-коду с учётом типовых задержек Xilinx Spartan-6** (LUT6 I→O ≈ 0.35 ns, CARRY4 carry/bit ≈ 0.075 ns, FF setup ≈ 0.46 ns, clk→Q ≈ 0.57 ns, routing-коэффициент ≈ 1.35). Реальный синтез в Xilinx ISE не выполнялся, отчётов `trce`/`timing` нет. Ожидаемая погрешность без реального синтеза — **±20–25%**. Для точного Fmax необходимо запустить `xst` + `trce` с `.ucf` ограничением на тактовую частоту.

#### Методика оценки Fmax

Fmax определяется самым длинным комбинационным путём между регистрами (reg-to-reg) плюс время установки (setup) выходного триггера:

```
T_clk ≥ T_clk→Q + T_logic(max path) + T_routing + T_setup
Fmax = 1 / T_clk
```

Учитываются только критические пути, описанные в секции «Критический путь (Timing)» для каждого модуля. Routing задержка оценивается как +35% к чистой логике.

#### Правила подсчёта LUT6:
- любая булева функция от ≤6 входов = 1 LUT6;
- n-битный сумматор/вычитатель с carry chain (CARRY4) = n LUTs — перенос идёт через MUXCY, а не через LUT;
- 2:1 мультиплексор шириной n бит = n LUTs;
- сравнение ниббла с константой (NOR4/AND4) = 1 LUT.

## Критический путь (Timing)

### RTZ:
```
mul4x4 (CSA) → mul_u8_u8_u16_lat2 CPA → exp_sum + man_msb → c_next mux → output reg
```
~5.2–6.2 ns (160–175–200 MHz). Критический путь проходит через 9-битный инкремент экспоненты (CARRY4), компараторы vs 381/254 и 5-ветвевой приоритетный mux `c_next`.

### RNE:
```
mul4x4 (CSA) → mul_u8_u8_u16_lat2 CPA → man_shifted/G/R/S → RNE increment → exp_inc → exp_norm (полное 9-битное сложение) → c_next mux → output reg
```
~5.6–6.4–7.1 ns (140–155–180 MHz). В отличие от RTZ, в критический путь вступают **две последовательные carry-цепочки** (инкремент мантиссы + сложение экспоненты), что снижает Fmax на ~10–15%.

### F32:
```
mul4x4_comb (CSA) → CPA → leading-one → mant_norm шейфер → exp_unb → F32 pack mux → output reg
```
~6.1–6.9–7.7 ns (130–145–165 MHz). Самый длинный такт — переход STAGE 2→STAGE 3: leading-one encoder (casez на 16 бит) + переменный сдвиг мантиссы (баррел-шейфер 24 бита).

### AddF32 RTZ:
```
баррел-шейфер выравнивания (S1) → 28-bit add/sub (S2) → LZD 27-bit (S3)
→ carry fix-up → F32 pack mux → output reg
```
~6.5–8.0–10.0 ns (90–120–150 MHz). Критический путь проходит через баррел-шейфер выравнивания мантисс на S1 и 28-битный CPA на S2.

### AddF32 RNE:
```
баррел-шейфер выравнивания (S1) → 28-bit add/sub (S2) → LZD 27-bit (S3)
→ нормализация → RNE rounding (G/R/S + инкремент) → F32 pack mux → output reg
```
~7.0–8.5–10.5 ns (80–110–140 MHz). В отличие от RTZ, в критический путь вступает дополнительная логика округления (sticky в LSB, G/R/S, инкремент significand).

### AddF16 RTZ:
```
баррел-шейфер выравнивания (S1) → 15-bit add/sub (S2) → LZD 15-bit (S3)
→ carry fix-up → F16 pack mux → output reg
```
~5.5–7.0–9.0 ns (110–140–180 MHz). FP16 вариант быстрее FP32 на ~20–25% за счёт уменьшенной разрядности всех путей.

### AddF16 RNE:
```
баррел-шейфер выравнивания (S1) → 15-bit add/sub (S2) → LZD 15-bit (S3)
→ нормализация → RNE rounding (G/R/S + инкремент) → F16 pack mux → output reg
```
~6.0–7.5–9.5 ns (100–130–165 MHz). В отличие от RTZ, в критический путь вступает дополнительная логика округления (sticky в LSB, G/R/S, инкремент significand).

### DSP48 для FP32 аддеров (`add_fp32_fp32_fp32_*`)

DSP48A1 **не применим** для FP32 аддеров без существенной переработки архитектуры:
- баррел-шейфер выравнивания мантисс (27 бит, переменный сдвиг) — не отображается на DSP48;
- LZD (leading-zero detect) — не отображается на DSP48;
- логика округления RNE (sticky, G/R/S, инкремент significand) — не отображается на DSP48;
- F32 pack mux (5 ветвей × 32 бита) — не отображается на DSP48;
- 28-битный add/sub теоретически помещается частично в порт A (25 бит) DSP48A1, но накладные расходы на конкатенацию частей и обратную сборку результата перекрывают любую экономию LUT.

**Ожидаемая экономия при использовании DSP48A1 для аддеров: 0 LUT.**

### DSP48 для FP16 аддеров (`add_fp16_fp16_fp16_*`)

Те же ограничения, что и для FP32 аддеров: баррел-шейфер, LZD, логика округления и F16 pack не отображаются на DSP48A1. 15-битный add/sub частично помещается в порт A (25 бит) DSP48A1, но накладные расходы перекрывают любую экономию LUT.

**Ожидаемая экономия при использовании DSP48A1 для аддеров: 0 LUT.**
