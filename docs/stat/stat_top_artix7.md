# Статистика реализации на Xilinx Artix-7 (XC7A15T)

## Спецификация целевого FPGA

| Параметр | Значение |
|----------|----------|
| **Device** | XC7A15T (Artix-7) |
| **Package** | varies (e.g. CPG236, CSG324, CSG325) |
| **Slices** | 2,600 |
| **LUTs (6-input / LUT6)** | **10,400** (2,600 × 4) |
| **Flip-Flops** | 20,800 |
| **Block RAM (36Kb)** | 25 (900 Kb total) |
| **DSP48E1** | 45 |
| **Speed grade** | -1 |
| **Целевая температура** | Коммерческий диапазон (0..85 °C) |
| **Max Clock (typical)** | ~280–450 MHz для простых путей |

---

> **Важно:** Все цифры ниже — **оценки на основе ручного подсчёта по RTL-коду с учётом типовых задержек Xilinx Artix-7** (LUT6 I→O ≈ 0.38 ns, CARRY4 carry/bit ≈ 0.045 ns, FF setup ≈ 0.48 ns, clk→Q ≈ 0.62 ns, routing-коэффициент ≈ 1.35). Реальный синтез в Xilinx Vivado не выполнялся, отчётов `report_timing` нет. Ожидаемая погрешность без реального синтеза — **±20–25%**. Для точного Fmax необходимо запустить `synth_design` + `report_timing` с `.xdc` ограничением на тактовую частоту.

#### Методика оценки Fmax

Fmax определяется самым длинным комбинационным путём между регистрами (reg-to-reg) плюс время установки (setup) выходного триггера:

```
T_clk ≥ T_clk→Q + T_logic(max path) + T_routing + T_setup
Fmax = 1 / T_clk
```

Routing задержка оценивается как +35% к чистой логике.

#### Правила подсчёта LUT6:
- любая булева функция от ≤6 входов = 1 LUT6;
- n-битный сумматор/вычитатель с carry chain (CARRY4) = n LUTs — перенос идёт через MUXCY, а не через LUT;
- 2:1 мультиплексор шириной n бит = n LUTs;
- сравнение ниббла с константой (NOR4/AND4) = 1 LUT.

| **Рабочая частота (typ)** | **~145 MHz** | — |

Fused multiply-add: единственное RNE-округление применяется к результату
`SUMM + VALA × VALB`; промежуточное произведение BF16 × BF16 точное (16 бит)
и не округляется до FP32/Inf. Субнормали BF16 и FP32 не флашатся в ноль.
NaN — канонический `0x7FC00000`.

Структурная проверка Yosys (`synth -noabc`, включая 4× `mul4x4_comb`):
3935 логических ячеек и 246 FF. LUT-маппинг ABC в YoWASP недоступен
(нет внешнего `yosys-abc`), поэтому LUT-оценка — ручная по той же методике.

## Критический путь (Timing)

### RTZ:
```
mul4x4 (CSA) → mul_u8_u8_u16_lat2 CPA → exp_sum + man_msb → c_next mux → output reg
```
~3.8–4.3–5.0 ns (~200–230–260 MHz).

### RNE:
```
mul4x4 (CSA) → mul_u8_u8_u16_lat2 CPA → man_shifted/G/R/S → RNE increment → exp_inc → exp_norm → c_next mux → output reg
```
~4.2–4.8–5.6 ns (~180–210–240 MHz).

### F32:
```
mul4x4_comb (CSA) → CPA → leading-one → mant_norm шейфер → exp_unb → F32 pack mux → output reg
```
~4.6–5.2–5.9 ns (~170–190–215 MHz).

### AddF32 RTZ:
```
баррел-шейфер выравнивания (S1) → 28-bit add/sub (S2) → LZD 27-bit (S3)
→ carry fix-up → F32 pack mux → output reg
```
~4.5–6.0–7.5 ns (~130–160–195 MHz). Критический путь проходит через баррел-шейфер выравнивания мантисс на S1 и 28-битный CPA на S2.

### AddF32 RNE:
```
баррел-шейфер выравнивания (S1) → 28-bit add/sub (S2) → LZD 27-bit (S3)
→ нормализация → RNE rounding (G/R/S + инкремент) → F32 pack mux → output reg
```
~5.0–6.5–8.0 ns (~120–150–185 MHz). В отличие от RTZ, в критический путь вступает дополнительная логика округления (sticky в LSB, G/R/S, инкремент significand).

### AddF16 RTZ:
```
баррел-шейфер выравнивания (S1) → 15-bit add/sub (S2) → LZD 15-bit (S3)
→ carry fix-up → F16 pack mux → output reg
```
~4.0–5.5–7.0 ns (~140–180–230 MHz). FP16 вариант быстрее FP32 на ~20–25% за счёт уменьшенной разрядности всех путей.

### AddF16 RNE:
```
баррел-шейфер выравнивания (S1) → 15-bit add/sub (S2) → LZD 15-bit (S3)
→ нормализация → RNE rounding (G/R/S + инкремент) → F16 pack mux → output reg
```
~4.5–6.0–7.5 ns (~130–165–210 MHz). В отличие от RTZ, в критический путь вступает дополнительная логика округления (sticky в LSB, G/R/S, инкремент significand).

### AddBF16 RTZ:
```
баррел-шейфер выравнивания (S1) → 15-bit add/sub (S2) → LZD 15-bit (S3)
→ carry fix-up → BF16 pack mux → output reg
```
~4.2–5.6–7.2 ns (~155–195–245 MHz). BF16-вариант близок к FP16; более широкие сравнения экспоненты (8 бит против 5) компенсируются упрощённой упаковкой (canonical NaN, RTZ overflow → max finite).

### AddBF16 RNE:
```
баррел-шейфер выравнивания (S1) → 15-bit add/sub (S2) → LZD 15-bit (S3)
→ нормализация → RNE rounding (G/R/S + инкремент) → BF16 pack mux → output reg
```
~4.7–6.1–7.8 ns (~145–180–225 MHz). В отличие от RTZ, в критический путь вступает дополнительная логика округления (sticky в LSB, G/R/S, инкремент significand).

### FMA RNE:
```
p_*_d1 → CSA-дерево → 16-bit CPA → k_calc → exp_p_calc
→ сравнение экспонент → shift_diff → large/small mux
→ 27-bit alignment shifter → регистр S3
```
~5.5–6.9–8.7 ns (~115–145–180 MHz). Самый длинный такт — S2: CSA/CPA произведения, приоритетный энкодер `k_calc`, сумматор экспоненты, знаковое сравнение экспонент и выравнивающий шейфер 27 бит.

> сокращает RTZ top до **~190-240 LUTs (~1.8-2.3%)**.

### DSP48 для FP32 аддеров (`add_fp32_fp32_fp32_*`)

DSP48E1 **не применим** для FP32 аддеров без существенной переработки архитектуры:
- баррел-шейфер выравнивания мантисс (27 бит, переменный сдвиг) — не отображается на DSP48;
- LZD (leading-zero detect) — не отображается на DSP48;
- логика округления RNE (sticky, G/R/S, инкремент significand) — не отображается на DSP48;
- F32 pack mux (5 ветвей × 32 бита) — не отображается на DSP48;
- 28-битный add/sub теоретически помещается частично в порт A (25 бит) DSP48E1, но накладные расходы на конкатенацию частей и обратную сборку результата перекрывают любую экономию LUT.

**Ожидаемая экономия при использовании DSP48E1 для аддеров: 0 LUT.**

### DSP48 для FP16 аддеров (`add_fp16_fp16_fp16_*`)

Те же ограничения, что и для FP32 аддеров: баррел-шейфер, LZD, логика округления и F16 pack не отображаются на DSP48E1. 15-битный add/sub частично помещается в порт A (25 бит) DSP48E1, но накладные расходы перекрывают любую экономию LUT.

**Ожидаемая экономия при использовании DSP48E1 для аддеров: 0 LUT.**
