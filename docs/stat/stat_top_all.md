## Краткие выводы

1. **Все модули очень компактны.** Даже на наименьшем устройстве (XC6SLX9) самый прожорливый модуль (`vhfastmulb16_rne_lat3`) занимает всего ~7.5% LUT6 и ~1.3% FF.

2. **RNE дороже RTZ на ~35 LUTs (~8%).** Это стоимость IEEE 754 округления "до ближайшего чётного" (G/R/S биты, инкремент мантиссы, корректировка экспоненты).

3. **F32-модуль эффективнее по LUT, но потребляет больше FF.** `vhfastmulb16_f32_lat4` использует комбинационный `mul4x4_comb` на первой стадии (экономия LUT) и глубокий 4-стадийный конвейер (больше FF). Latency = 4 такта вместо 3.

4. **Ресурсы 7-й серии (Spartan-7, Artix-7) ниже, чем Spartan-6** в процентном соотношении: загрузка одинакова (~392 LUT), а устройства больше.

5. **DSP48 потенциал.** Перенос `mul8x8` на 1× DSP48A1/DSP48E1 сэкономит ~200 LUT (~50% модуля), сокращая RTZ top до ~190-240 LUT (~1.8–4.2% в зависимости от устройства).

6. **Маржа для роста.** На всех целевых FPGA остаётся не менее **92% свободных LUT6** для остальной логики системы.

7. **Fmax требует верификации через реальный синтез.** Все цифры частоты — оценки по RTL без запуска Xilinx ISE/Vivado timing-анализатора. Ожидаемая погрешность **±20–25%**. Для точного Fmax необходимо выполнить синтез с `report_timing` (или `trce` для Spartan-6) и `.xdc`/`.ucf` ограничением на тактовую частоту.
