| Параметр | XC7S15-1 | XC7S15-2 |
|----------|----------|----------|
| **Device** | XC7S15-1FTGB196C (Spartan-7) | XC7S15-2CPGA196I (Spartan-7) |

| **Slices** | 2,000 | 2,000 |
| **LUTs (6-input / LUT6)** | **8,000** (2,000 × 4) | **8,000** (2,000 × 4) |
| **Flip-Flops** | 16,000 | 16,000 |
| **Block RAM (36Kb)** | 10 (360 Kb total) | 10 (360 Kb total) |

---

> **Важно:** Все цифры ниже — **оценки на основе ручного подсчёта по RTL-коду с учётом типовых задержек Xilinx Spartan-7** (LUT6 I→O ≈ 0.36..0.42 ns, CARRY4 carry/bit ≈ 0.042..0.050 ns, FF setup ≈ 0.45..0.52 ns, clk→Q ≈ 0.59..0.68 ns, routing-коэффициент ≈ 1.35..1.40). Реальный синтез в Xilinx Vivado не выполнялся, отчётов `report_timing` нет. Ожидаемая погрешность без реального синтеза — **±20–25%**. Для точного Fmax необходимо запустить `synth_design` + `report_timing` с `.xdc` ограничением на тактовую частоту.

#### Методика оценки Fmax

Fmax определяется самым длинным комбинационным путём между регистрами (reg-to-reg) плюс время установки (setup) выходного триггера:

```
T_clk ≥ T_clk→Q + T_logic(max path) + T_routing + T_setup
Fmax = 1 / T_clk
```

Speed grade -2 примерно на 12–15% быстрее speed grade -1. Routing задержка оценивается как +35..40% к чистой логике.

#### Правила подсчёта LUT6:
- любая булева функция от ≤6 входов = 1 LUT6;
- n-битный сумматор/вычитатель с carry chain (CARRY4) = n LUTs — перенос идёт через MUXCY, а не через LUT;
- 2:1 мультиплексор шириной n бит = n LUTs;
- сравнение ниббла с константой (NOR4/AND4) = 1 LUT.

## Критический путь (Timing)

### RTZ:
```
mul4x4 (CSA) → mul_u8_u8_u16_lat2 CPA → exp_sum + man_msb → c_next mux → output reg
```
~4.2–4.7–5.6 ns (XC7S15-1: 180–205–240 MHz; XC7S15-2: 200–225–260 MHz).

### RNE:
```
mul4x4 (CSA) → mul_u8_u8_u16_lat2 CPA → man_shifted/G/R/S → RNE increment → exp_inc → exp_norm → c_next mux → output reg
```
~4.8–5.5–6.2 ns (XC7S15-1: 160–180–210 MHz; XC7S15-2: 180–200–230 MHz).

### F32:
```
mul4x4_comb (CSA) → CPA → leading-one → mant_norm шейфер → exp_unb → F32 pack mux → output reg
```
~5.3–6.0–6.7 ns (XC7S15-1: 150–165–190 MHz; XC7S15-2: 165–180–205 MHz).

### AddF32 RTZ:
```
баррел-шейфер выравнивания (S1) → 28-bit add/sub (S2) → LZD 27-bit (S3)
→ carry fix-up → F32 pack mux → output reg
```
~5.0–6.5–8.0 ns (XC7S15-1: 110–140–170 MHz; XC7S15-2: 120–150–185 MHz).

### AddF32 RNE:
```
баррел-шейфер выравнивания (S1) → 28-bit add/sub (S2) → LZD 27-bit (S3)
→ нормализация → RNE rounding (G/R/S + инкремент) → F32 pack mux → output reg
```
~5.5–7.0–8.5 ns (XC7S15-1: 100–130–160 MHz; XC7S15-2: 110–140–175 MHz). В отличие от RTZ, в критический путь вступает дополнительная логика округления (sticky в LSB, G/R/S, инкремент significand).

### AddF16 RTZ:
```
баррел-шейфер выравнивания (S1) → 15-bit add/sub (S2) → LZD 15-bit (S3)
→ carry fix-up → F16 pack mux → output reg
```
~4.5–6.0–7.5 ns (XC7S15-1: 135–170–210 MHz; XC7S15-2: 150–190–230 MHz). FP16 вариант быстрее FP32 на ~20–25% за счёт уменьшенной разрядности всех путей.

### AddF16 RNE:
```
баррел-шейфер выравнивания (S1) → 15-bit add/sub (S2) → LZD 15-bit (S3)
→ нормализация → RNE rounding (G/R/S + инкремент) → F16 pack mux → output reg
```
~5.0–6.5–8.0 ns (XC7S15-1: 125–155–195 MHz; XC7S15-2: 140–175–215 MHz). В отличие от RTZ, в критический путь вступает дополнительная логика округления (sticky в LSB, G/R/S, инкремент significand).

## Рекомендации по оптимизации

| Оптимизация | Экономия LUTs | Сложность |
|-------------|---------------|-----------|
| Перенести `mul_u8_u8_u16_lat2` на DSP48E1 | ~-200 LUTs | 1× DSP48E1 (25×18 multiplier) |
| Убрать избыточные mux `*_exp_eff` | ~-16 LUTs | Простейшая правка |
| Объединить `except_lat2` + `flags_lat1` | ~-10 LUTs | Рефакторинг флагов |
| **Потенциальный итог RTZ** | **~170-220 LUTs (~2-3%)** | |

> Spartan-7 XC7S15 имеет **20 DSP48E1**. Использование 1 для `mul_u8_u8_u16_lat2`
> сокращает RTZ top до **~190-240 LUTs (~2.4-3.0%)**.

### DSP48 для FP32 аддеров (`add_fp32_*`)

DSP48E1 **не применим** для FP32 аддеров без существенной переработки архитектуры:
- баррел-шейфер выравнивания мантисс (27 бит, переменный сдвиг) — не отображается на DSP48;
- LZD (leading-zero detect) — не отображается на DSP48;
- логика округления RNE (sticky, G/R/S, инкремент significand) — не отображается на DSP48;
- F32 pack mux (5 ветвей × 32 бита) — не отображается на DSP48;
- 28-битный add/sub теоретически помещается частично в порт A (25 бит) DSP48E1, но накладные расходы на конкатенацию частей и обратную сборку результата перекрывают любую экономию LUT.

**Ожидаемая экономия при использовании DSP48E1 для аддеров: 0 LUT.**

### DSP48 для FP16 аддеров (`add_fp16_*`)

Те же ограничения, что и для FP32 аддеров: баррел-шейфер, LZD, логика округления и F16 pack не отображаются на DSP48E1. 15-битный add/sub частично помещается в порт A (25 бит) DSP48E1, но накладные расходы перекрывают любую экономию LUT.

**Ожидаемая экономия при использовании DSP48E1 для аддеров: 0 LUT.**
