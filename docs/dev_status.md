# Development Status

- The BF16-output top-level modules `vhfastmulb16_mul_bf16_bf16_bf16_rtz_lat3` and `vhfastmulb16_mul_bf16_bf16_bf16_rne_lat3` are available (latency 3).
- The FAST BF16-output top-level module `vhfastmulb16_mul_bf16_bf16_bf16_fst_lat3` is available (latency 3): speed-optimized variant with a single 3-stage pipeline (no nested latency modules), RTZ rounding, FTZ inputs, canonical qNaN `0x7FC0` (no sign), sign XOR on Inf/zero/normal; autonomous (only 4× `vhfastmulb16_mul4x4_comb`, 0 DSP). Synthesis (YoWASP, LUT estimate): ~230 LUT, ~61 FF, ~230 MHz on XC7S15-1 (vs ~252 LUT / ~106 FF / 205 MHz for `rtz_lat3`).
- The F32-output top-level module `vhfastmulb16_mul_bf16_bf16_fp32_lat4` is available (latency 4): exact BF16 x BF16 product represented as IEEE-754 binary32, no rounding, BF16 subnormals are not flushed, F32 subnormal results are truncated (RTZ).
- The FMA top-level module `vhfastmulb16_muladd_bf16_bf16_fp32_fp32_rne_lat4` is available (latency 4): fused `SUMM + VALA × VALB` with a single RNE rounding, exact BF16 product, BF16 and FP32 subnormals are not flushed, and an exact intermediate product is not rounded to Inf before the final addition.
- The FMA top-level module `vhfastmulb16_muladd_bf16_bf16_fp32_fp32_rne_lat8` is available (latency 8): same fused FMA functionality with an 8-stage balanced pipeline optimized for maximum Fmax. Key optimizations: rebalanced 8 stages (S1: decode + 4×mul4x4 + exp_p0/exp_s0 + clz24; S2: 2-level CSA + SUMM normalization; S3: CPA → man_prod + LOD k; S4: p24, exp_p + k, direct exp_p - exp_s; S5: sticky + alignment; S6: add/sub + carry fix-up + LZD; S7: normalization + parallel CARRY4 subtractors for exp_pre/grs_shift; S8: RNE + pack), direct shift_diff without mux on shift-amount path, parallel CARRY4 subtractors replacing prefix network, per-stage clock enable (en_d1..en_d7) with true CE on FDRE (no bubble insertion on en=0).
- The FAST FMA top-level module `vhfastmulb16_muladd_bf16_bf16_fp32_fp32_fst_lat8` is available (latency 8): speed-optimized variant of the BF16 × BF16 + FP32 FMA with RTZ (truncation) and FTZ on BF16/FP32 subnormals. The 8-stage pipeline removes the RNE G/R/S logic, the SUMM CLZ24/normalization, the 16-way product LOD, the prefix-OR sticky tree and the subnormal output path; the product is still exact and the single final rounding is RTZ. Zero results are always `+0`; overflow -> `±Inf`; NaN -> canonical `0x7FC00000`.
- The FAST FMA top-level module `vhfastmulb16_muladd_bf16_bf16_fp32_fp32_fst_lat4` is available (latency 4): same RTZ/FTZ contract as `..._fst_lat8` (bit-exact; 1-bit product normalization, no sticky, no carry OR), rebalanced into 4 stages (S1 decode+FTZ+4×mul4x4, S2 CSA+CPA+1-bit norm+exp diff+large/small+alignment, S3 28-bit add+LZD+normalize+exp_f32, S4 RTZ pack). Synthesis (YoWASP, LUT estimate): ~667 LUT, 234 FF, 0 DSP; Fmax typ 170/200/220 MHz (vs ~667 LUT / 528 FF / 200–250 MHz for `..._fst_lat8`): ~2× fewer FF, lower Fmax. First post-PAR trial (2026-11-21, Xilinx ISE 14.7, CMB32F407HDMIR3, XC6SLX9-2TQG144, logs in [`docs/benchmarks/log_fma_fst_lat4/`](benchmarks/log_fma_fst_lat4/)): **0 timing errors**, min period 7.987 ns (≈125.2 MHz) for the whole top under a 10 ns constraint; worst internal DUT path `grp_mul` 9.357 ns (≈106.9 MHz, 8 logic levels); **493 slice FF / 759 slice LUT / 0 DSP48A1** (vs 890 / 802 / 0 for lat=8) — confirms the ~2× FF reduction.

- The FMA top-level module `vhfma001` is available (latency 8): speed-optimized clone of the lat8 FMA (S2 prefix-CLZ, S4 nonzero-gate for the mantissa compare, S7 shift-of-shift removal — subnormal GRS computed directly from S6 registers, S7/S8 exponent retiming), identical latency, interface and control model to lat8; pure LUT/FF implementation.
- The FMA top-level module `vhfma002` is available (latency 8): experimental variant of `vhfma001` with the 8x8 BF16 mantissa multiply mapped to a single DSP48 block (`*` with `use_dsp="yes"`) — the only module of the library allowed to use DSP blocks. Reworked on 2026-11-16: single DSP-mapped multiply replacing four LUT 4x4 multipliers, product CLZ16 one-hot decoder replacing the `casez` priority leading-one detect, dead logic removed; see [DSP Block Exception](../README.md#dsp-block-exception-vhfma002).

- The modules are implemented in pure logic; the multiplication operator `*` appears **only** in `vhfma002` (DSP48-mapped, explicitly allowed exception). **Use of DSP blocks (DSP48A1, DSP48E1, etc.) is prohibited for all other modules** to ensure portability across FPGA families; see [DSP Block Exception](../README.md#dsp-block-exception-vhfma002).
